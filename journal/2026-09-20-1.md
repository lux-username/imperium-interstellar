# 2026-09-20 — Session 2: core types

## What was done

Started with the user asking for an explanation of issue #1 before committing to it. Walked through why the ground-truth / belief split has to be in the type system first, then built it in a worktree branch.

- `src/sim/types.ts` — ground truth: branded ids (`Id<Kind>`), `Week`, `Address`/`Location`, `World` + `WorldProfile` (our own code ranges), `Lane` + `PacketSchedule`, minimal `Ship`/`Character`/`Faction`, `Mail` + `MailStatus` (one in-flight wrapper for both reports and dispatches), `GameState` with per-character `beliefs`.
- `src/sim/view.ts` — player-visible: `Report`, `WorldSnapshot`/`ShipSnapshot`, `Envelope`, `Dispatch`, `Belief`, `PlayerView`. Re-exports the safe primitives so the UI never imports `types.ts`.
- `src/sim/orders.ts` — Phase 0 `Order` union (`hold`, `move`, `courier`), kept in its own file because CLAUDE.md derives the order list by grepping it.
- `src/sim/types.test.ts` — JSON round-trip of a fixture `GameState`; `expectTypeOf` checks that ids don't cross kinds, that `World` ≠ `WorldSnapshot`, and that `PlayerView` has no `worlds`/`rng`.
- Merged as PR #10 (merge commit `5dd7bc1`).
- Fixed the `Test count` command in CLAUDE.md's Derived Facts table (`NO_COLOR=1`), which was returning nothing because vitest colours its summary.
